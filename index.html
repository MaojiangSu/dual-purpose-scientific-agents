Dual-Purpose Experimental Design

Benchmarking and Improving Scientific Agents

Maojiang SuHan Liu

Center for Foundation Models and Generative AI
Northwestern University

AbstractOverviewProblem SetupMethodExperiments

Abstract

Experimental feedback serves two purposes in scientific design: benchmarking scientific agents and providing verified evidence for subsequent learning. However, under a limited experimental query budget, the items most useful for distinguishing agents may not be those most useful for improving them. To address this trade-off, we study dual-purpose experimental design, where each agent independently performs multiple runs on the same scientific item, and the acquired experimental feedback supports both agent benchmarking and subsequent improvement. We propose an adaptive sampling strategy that balances benchmarking and learning through separate sample-value estimates. As experimental results become available, the strategy updates its value predictors and selects which items to verify next. We analyze finite-run variability, the outcome dependence of benchmarking values, and the distinction between a selection proxy and benchmark reliability. We evaluate a lightweight learning operator that updates external experimental memory while keeping the underlying language model frozen. On held-out GB1 variant pairs, this memory improves the target agent's accuracy from 63.3% to 69.5%; at a matched 384-item budget, adaptive Joint selection reaches 70.12% versus 69.27% for random selection, but has higher benchmark mean-score error. These results demonstrate useful experimental-memory learning while exposing a limitation of the current dual-objective estimator.

One Experiment, Two Uses

Choose which scientific item to verify next. Use the same experimental outcome to benchmark fixed agents and improve a target agent.

Why Dual-Purpose Experimental Design?

Experimental ground truth supports two scientific uses: comparing agents and improving a target agent. Both depend on verified outcomes, and both compete for a limited experimental query budget.

A task that clearly separates competing agents may provide little new evidence for learning. A useful training item may contribute little to benchmark discrimination. We therefore choose which items to verify by treating benchmarking and learning as two objectives that evolve with the acquired feedback.

Problem Setup

We start with a pool of scientific items whose experimental outcomes are hidden. A policy selects items sequentially under one query budget; each acquired outcome supports both the fixed reference panel and an improving target.

Scientific Items
Each item has public context, an unknown experimental outcome and a declared query cost. In the protein setting, one item is a pair of variants; verification reveals two fitness values and costs two measurements.
Reference Agents And Multi-Runs
A fixed panel of agents answers each item independently several times before verification. Cached answers become benchmark scores only after the experimental outcome is acquired. Multi-runs measure variability within the same agent.
The Improving Target
A separate target agent changes its external experimental memory as evidence accumulates. Its base language model and fallback prompt remain fixed, as does the reference panel.

Two Objectives Under The Same Budget

1. Benchmarking

Build a verified set that separates reference-agent mean scores relative to their run-to-run variation. The paper uses a set-level signal-to-noise ratio, denoted by F.

F(S)=between-agent separationwithin-agent variation+ϵF(S)=\frac{\text{between-agent separation}}{\text{within-agent variation}+\epsilon}F(S)=within-agent variation+ϵbetween-agent separation​

Larger separation relative to run variability gives a higher discrimination score.

2. Learning

Acquire evidence that improves the target agent on independent held-out items. Learning value depends on the current memory, the acquired data and the update procedure.

Compare the final target with its initial state on the same held-out test set.

The policy seeks a trade-off between these objectives while staying within the shared budget. The common warm-up counts toward that budget.

Explicit Benchmarking Sample Value

An item's benchmarking value is the change it makes to the current verified set's discrimination score:

vbench(z∣S)=F(S∪{z})−F(S)v_{\mathrm{bench}}(z\mid S)=F(S\cup\{z\})-F(S)vbench​(z∣S)=F(S∪{z})−F(S)

Here S is the current verified set and z is a candidate item. The marginal can be negative. It guides selection; independent audit runs assess benchmark mean-score error and ranking fidelity.

For learning, the ideal value is the expected future improvement after using the item's feedback. We estimate it from measured Development gains after small update batches. One batch supplies one regression observation, not an independent gain label for each item.

Adaptive Item Selection

The method alternates between selecting experimental items and updating the target's external memory. New feedback refreshes both value estimators, allowing later choices to depend on earlier results.

  1. Warm Up

    Query a shared random set to initialize the outcome predictor, experimental memory and batch-level learning feedback.

  2. Estimate Both Values And Select

    Predict the benchmarking marginal and learning potential of each remaining item. Combine normalized values and exploration bonuses per unit cost, then select an affordable item.

  3. Verify Once, Reuse Twice

    Pay the query cost and reveal the outcome. Score all cached reference runs, add the measurements to training evidence, and refresh the benchmarking predictor.

  4. Update Memory And Repeat

    After a small batch, fit a candidate memory and retain it only if Development performance improves. Record both proposed and accepted gains to update the learning predictor, then continue until the budget is exhausted.

How The Values Are Estimated

The benchmarking predictor combines exact sample values under possible outcomes with estimated outcome probabilities. The learning predictor uses item and memory features together with earlier batch-update gains. These working estimates are updated as verified data arrive.

The displayed base score mixes normalized benchmarking and learning values with preference λ and divides by query cost. The implemented strategy also uses exploration bonuses and occasional random queries.

Development chooses memory updates; an independent final test evaluates generalization. An accepted Development update does not guarantee held-out improvement.

One Result Has Two Uses

1. Benchmark The Agents

After verification, compare every cached A/B answer with the measured winner.

2. Supply Experimental Memory

Both labeled variants become training evidence for the target's external fitness predictor.

After warm-up, memory updates are proposed every eight verified tasks.

In the full algorithm, new assay outcomes refresh benchmarking predictions. After each eight-item batch, a candidate memory is fitted and tested on Development; accepted and rejected update gains train the learning-value predictor.

What Have We Actually Tested?

We separate two questions: can feedback improve an agent? And does our selection algorithm use the same budget better?

Experiment 1 · Learning Feasibility

Can Verified Protein Feedback Improve A Frozen Agent?

We learned an external GB1 fitness predictor from acquired measurements. A fixed routing rule consults this memory when its preference is strong; otherwise it keeps Terra's answer. The LLM weights and fallback prompt stay fixed.

The selected snapshot uses 256 training pairs. The Development search acquired 1,024 training pairs in total, then froze the memory and routing threshold before testing on 256 held-out pairs with two fresh runs each.

What Worked

Held-out accuracy increased from 63.28% to 69.53%: a gain of 6.25 percentage points on unseen combinations within GB1.

What This Does Not Establish

This confirms a useful external memory in one protein setting. It does not prove that adaptive item selection beats Random.

Experiment 2 · Equal-Budget Selection

Does Adaptive Selection Beat Random?

A new split gives every policy the same candidate pool, updater and query costs. We compare six selection strategies using Terra and Sol as fixed reference agents, with Terra as the improving target.

Learning Result At 384 Items

Adaptive Joint: 70.12%. Random: 69.27%. Static Joint: 70.31%. The adaptive version has a small observed gain over Random, and does not exceed Static Joint.

The Joint Trade-Off Is Not Yet Better

Random estimates agent means more accurately. Adaptive Joint's benchmark MSE is about 21.5 times larger. Its learning-gain predictor also loses to predicting zero gain.

Experiment 3 · Transfer Diagnostic

Does The Memory Transfer Across Proteins?

A separate feature-memory configuration was tested on 96 pairs from 12 unseen UniProt groups. Original Terra reached 69.79%; the memory version reached 66.67%. That configuration did not improve cross-protein performance.

This is a different memory configuration from the interaction-aware GB1 model. The positive GB1 result concerns new combinations within the same protein.

What Needs To Be Tested Next?

More scale will be useful after we understand the current estimator failures. The next tests focus on the following questions.

  1. Can We Predict Which Feedback Helps Learning?

    Replay saved batches. Compare predicted gain with measured signed and accepted gain, alongside zero and past-mean baselines. The present predictor has only 47 batch records per campaign and sparse accepted updates.

  2. Are We Selecting For The Benchmark We Want?

    Plot discrimination score and independent mean-score error together. Maximizing set-SNR need not minimize mean-estimation MSE; this objective mismatch must be resolved before claiming benchmark accuracy gains.

  3. Does The Same Memory Help Qwen Agents?

    Run matched Qwen3.5-9B and Qwen3.5-35B-A3B tests with the frozen memory and input protocol. Separate baseline ability, memory benefit and inference cost before expanding the reference panel.

  4. Does The Revised Allocator Generalize?

    Freeze the updater, predictors and evaluation target, then compare Random, Static and Adaptive selection on a new variant-disjoint split. Report both learning accuracy and benchmark fidelity at the prespecified budget.

Theory And Update Details

What The Analysis Establishes

Finite-run variability contributes to apparent agent separation. A single valid binary item has the same SNR under either non-tie winner, motivating a set-level marginal. Bounded sample values and feasible query accounting do not imply unbiased benchmark estimates, positive test gain or globally optimal selection.

Memory Update Schedule

The first memory fit uses 16 acquired tasks, followed by a proposal every eight tasks. Candidate memories use acquired outcomes only. Evaluation uses a fixed Development response bank, and no per-task LLM editor call is required.
